# Moves deck

Give each direction **2–3 additive moves** and **at most one** restrictive constraint. Additive
moves bring energy. Constraints remove things, and too many leave an empty page. Write the chosen
moves into `DESIGN.md` so they hold for the whole project.

## Additive moves

### Image
- **Full-bleed hero visual:** one big, art-directed image, 3D scene or video loop of the real
  product/place, with type set against it.
- **Macro detail:** extreme close-ups of the subject's materials (solder joints, fabric weave,
  coffee crema) as section openers.
- **3D product scene:** a three.js / R3F model the user can rotate or that assembles on scroll
  (a PCB building up its layers, a device opening up).
- **Data as image:** real data rendered as a striking visual (routes on a map, live sensor
  traces, a timeline of shipped work).
- **One illustrator's hand:** a custom illustration style used consistently across sections and states.

### Color
- **Color fields per section/topic:** each discipline or chapter owns a strong background color; scrolling changes the world.
- **One loud color:** a single saturated brand color used in big areas, not as a thin accent.
- **Duotone imagery:** every photo/render processed into the brand's two colors so mixed sources feel like one set.

### Type
- **Display at scale:** headline type that fills the viewport width on desktop, with a characterful face.
- **Type × image:** type overlapping or masked by imagery; headline crossing an image edge.
- **Kinetic type:** words that move with scroll or respond to the cursor, in service of meaning.
- **Big numbers:** the client's real numbers set huge, labels small.

### Motion
- **Scroll story:** a pinned section where the scroll explains a process step by step (board → firmware → server → screen).
- **Signature transition:** one distinctive transition between pages or states, derived from the brand mark or subject.
- **Responsive matter:** elements with physics or springs that react to cursor/touch (subtle, purposeful).
- **Live element:** something real updating (a clock in the client's timezone, the latest deploy, a sensor value).

### Layout
- **Broken grid on purpose:** imagery and type that overlap section boundaries.
- **Horizontal chapter:** one section scrolls sideways (case studies, a timeline).
- **Pace contrast:** immersive full-screen → dense info → quiet breather, repeated with variation.
- **Interactive centerpiece:** one tool the visitor can use (configurator, estimate, picker) that demonstrates the value.

## Constraints (max one per direction)

- **One family only:** hierarchy from size/weight/width. Pair with strong image or color moves.
- **Grid from a real dimension:** ratios from the product (board size, plate, screen).
- **Light-first or dark-first** against expectation, with a reason.
- **No icon library:** text labels or a small custom set.
- **No cards:** grouping by space and alignment. Only if imagery carries the richness.

Never stack "monochrome + one family + no images + no motion". That's the sterile escape.
